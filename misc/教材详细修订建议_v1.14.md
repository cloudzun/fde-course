新增内容不应再讲一套新理论，而应让读者综合使用前文框架完成一次证据审查与决策。

### 建议结构

#### 1. 综合案例背景

选择一个贯穿全书的项目，例如“制造业供应链协同与缺料预警 Agent”，提供：

- 客户背景；
- 当前业务流程；
- 数据源和数据质量；
- 核心利益相关者；
- 业务痛点与初步价值假设；
- 合规与部署限制；
- 初始预算和时间边界。

#### 2. 五类证据

| 证据类别 | 主责角色 | 必须回答的问题 |
| :--- | :--- | :--- |
| 业务价值证据 | Echo | 是否解决了正确的问题，价值是否可测量 |
| 工程交付证据 | Delta | 方案是否能运行、能集成、能维护 |
| 生产就绪证据 | Engineering | 是否安全、稳定、可观测、可回滚 |
| 组织采纳证据 | Echo + 客户业务 | 用户是否愿意采用，客户能否自运营 |
| 平台回注证据 | Dev + Delta | 共性能力是否完成抽象并在第二场景复用 |

#### 3. 最终决策

最终答辩应允许四种结果：

- **Go**：价值、工程、组织和风险证据均达到生产标准；
- **Conditional Go**：原则上可以上线，但必须先完成明确整改；
- **Continue Pilot**：价值假设仍值得验证，但当前证据不足；
- **No-Go**：价值、数据、合规或组织条件不成立，应停止投入。

不得把“完成 Demo”默认等同于“应该上线”。

#### 4. 最终交付证据包

建议要求读者提交：

1. 利益相关者地图；
2. 快赢场景筛选矩阵；
3. 核心业务对象与 Ontology 草图；
4. Prototype 演示脚本；
5. 原型技术债清单；
6. Build 生产准入证据；
7. Eval 数据集与评测结果；
8. 权限、安全、监控和回滚方案；
9. Scale 与客户自运营路线；
10. 能力回注需求卡；
11. ROI 测算；
12. 最终交付决策书。

### 验收标准

- 综合任务覆盖 Discovery→Prototype→Build→Scale→能力回注；
- 包含 Echo、Delta、Engineering、Dev、Lead 和客户方责任；
- 结论允许 Go、Conditional Go、Continue Pilot、No-Go；

## P0-5　统一能力回注的验证标准

### 现状与问题

当前至少存在两种不同口径：

- 第9章9.1：由下一个项目或新的真实场景复用验证后，能力才“毕业”；
- 第8章8.6和第11章11.6：平台集成后由来源项目现场验证，容易被理解为回注已经完成。

“来源项目兼容性验证”和“第二场景通用性验证”是两类不同证据：

- 在原项目重新运行成功，只能证明重构没有破坏原业务；
- 在另一客户、项目或明显不同的业务场景中成功复用，才能证明它具有通用性。

### 建议统一为两级验证

#### V1：来源项目回归验证

目标：

- 确认平台化改造没有破坏原有功能；
- 确认接口、性能、权限和数据结果正常。

状态只能标为：

> **已集成／来源验证通过**

#### V2：第二场景复用验证

目标：

- 在另一客户、另一项目或显著不同的业务上下文中复用；
- 验证参数化能力；
- 验证没有隐含客户特化逻辑；
- 记录二次适配成本。

只有 V2 通过，才能标为：

> **已验证复用／毕业入库**

### 需要联动修改的位置

- 第8章8.6、8.8、8.9；
- 第9章9.1、9.3；
- 第11章11.6；
- 附录术语表和研讨题。

### 验收标准

- 全书只有一个“能力回注完成”定义；
- 来源项目验证不能被写成通用性验证；
- 未经过第二场景验证的能力不能进入“毕业入库”状态。

## P0-6　修正第15章 ROI 公式和回本周期

### 现状与问题

当前第15章将“AI FDE 年化价值”定义为：

$$
\text{人力节省}+\text{效率价值}+\text{风险降低}-\text{年合同额}
$$

随后又写：

> 年化价值 ≥ 2×年合同额，即两年内回本。

二者在财务意义上不一致。前面的“年化价值”已经扣除了合同额，更接近年度净收益，不能再按“达到合同额两倍”推导两年回本。

### 建议采用三个独立指标

#### 1. 年度总收益

$$
\text{年度总收益}
=
\text{人力节省}
+
\text{成本降低}
+
\text{增量收入}
+
\text{风险损失避免}
$$

#### 2. 项目 ROI

$$
\text{项目 ROI}
=
\frac{\text{项目周期内总收益}-\text{项目周期内总成本}}
{\text{项目周期内总成本}}
$$

#### 3. 静态回收期

$$
\text{静态回收期（月）}
=
\frac{\text{初始投资}}
{\text{月均净现金流入}}
$$

### 建议补充的边界说明

- 人力节省必须区分“释放工时”和“实际减少成本”；
- 风险避免价值应给出风险发生概率和损失口径；
- 后续复购预期不能直接作为已实现收益；
- 战略种子项目可以接受负 ROI，但必须说明换取的资产：行业知识、可复用组件、标杆客户、数据资产或市场进入权；
- “ROI 20%—30%”“年化收益达到合同额两倍”等阈值应明确标为教材示例，不构成通用投资标准。

### 验收标准

- 收益、净收益、ROI 和回收期概念不混用；
- 公式与文字结论一致；
- 所有决策阈值均标明是事实标准还是教材示例。

# 三、P1 级修订：显著提升知识结构与教学效果

虽然正文多处有说明，但标签位置和表达方式不统一，读者仍可能混淆。

### 建议标签

在每个案例标题旁直接标注：

- `[公开可核验]`
- `[匿名公开素材]`
- `[访谈脱敏]`
- `[教学合成]`

### 使用规则

- 真实企业名称＋真实数字：必须有直接来源；
- 真实企业名称＋无法核验数字：删除数字；
- 教学示意数字：不使用真实企业名称；
- 访谈数据：说明访谈时间、角色类型、脱敏方式和不可外推边界。

## P2-7　弱化绝对化表述

建议重点检查以下词语：

- 首创；
- 唯一；
- 第一；
- 国内首个；
- 事实标准；
- 全面适配；
- 必然；
- 一律；
- 绝大多数；
- 90%；
- 不进中国市场。

没有强来源时，建议改为：

- 较早系统化采用；
- 代表性路径之一；
- 公开报道显示；
- 在本教材所比较的模式中；
- 可作为优先选项；
- 通常；
- 在特定条件下。

## P2-8　区分“事实数据、教学示例阈值、组织决策参数”

### 容易被误读为行业标准的内容

- 70%平台＋30%定制；
- 20%时间用于回注；
- 连续2个冲刺未通过Gate；
- 累计投入超过预估150%触发止损；
- 至少3名冠军用户；
- 甲方自评勾选≥3条；
- 项目ROI 20%—30%。

### 建议统一标签

| 类型 | 含义 | 写法要求 |
| :--- | :--- | :--- |
| 事实数据 | 来自公开资料或正式统计 | 必须给来源和时间 |
| 教学示例阈值 | 用于课堂演算和说明 | 明确标注“示例，可按项目调整” |
| 组织决策参数 | 企业根据实际情况制定 | 给出设定方法，不给出伪通用标准 |

# 七、最终修订目标

修订后的全书应形成以下完整闭环：

> **认知FDE → 看懂标杆 → 掌握四阶段 → 明确角色责任 → 应对中国环境 → 落地AI解决方案 → 汇总业务、工程、组织和风险证据 → 作出是否上线与是否规模化的决策 → 将现场能力回注平台并在第二场景验证。**

最终应让读者明确：

- **Echo**确保解决的是正确问题，价值可证明，组织愿意采用；
- **Delta**确保方案能够构建、集成并形成业务闭环；
- **Engineering**确保系统安全、稳定、可观测、可回滚和可接管；
- **Dev**确保现场共性被正确抽象并进入平台；
- **Lead**确保范围、资源、Gate和跨角色决策成立；
- **商务与法务**确保价格、合同、知识产权和风险条款成立；
- **客户业务与IT**共同确认价值兑现与自运营条件。

本书当前已经不缺知识。下一轮修订的核心，是把现有知识整理成一个：

> **边界清楚、证据可靠、可以学习、可以实操、可以验收的完整体系。**
